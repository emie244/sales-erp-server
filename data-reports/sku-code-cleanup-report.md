## 规范编码格式

```
CP-AA-NNN      成品 (如 CP-DJ-001)
CP-AA-BB-NNN   成品子类 (如 CP-DJ-LD-001)
BC-AA-NNN      半成品
YL-AA-NNN      原材料
```

## 待清洗清单

### 1. UUID 兜底 (316 条) — 最高优先级

这些 SKU 没有有效的聚水潭关联，字段均为空。

```sql
SELECT "jst_sku_id", "skuCode", "skuName", category, brand
FROM product_skus
WHERE "skuCode" ~ '^[a-f0-9]{8}-[a-f0-9]{4}-[a-f0-9]{4}-[a-f0-9]{4}-[a-f0-9]{12}$';
```

**操作步骤**:

1. 在聚水潭后台为这 316 个商品补充 `sku_code`
2. 重新运行全量同步 (`sync-skus` job with daysBack=3650)
3. 同步后检查 `code_compliant` 是否变为 true

### 2. 13位数字兜底 (291 条) — 高优先级

这些 SKU 有有效的聚水潭关联，但 `sku_code` 为空，用了 `sku_id` 兜底。

```sql
SELECT "jst_sku_id", "skuCode", "skuName", category, brand
FROM product_skus
WHERE "skuCode" ~ '^[0-9]{13}$';
```

**操作步骤**:

1. 在聚水潭后台为这 291 个商品补充 `sku_code`
2. 重新运行全量同步
3. 由于代码已更新（#156），同步时会跳过无 sku_code 的记录，直到补充完成

### 3. 旧手工编码 (35 条) — 中优先级

`EMIE*` 和 `EM*` 格式的旧编码，需要按新规范重写。

**操作步骤**:

1. 确认每个 SKU 的物料分类（成品/半成品/原材料）
2. 按规范分配新编码（如 `CP-DJ-001`）
3. 在聚水潭更新 `sku_code`
4. 重新同步
