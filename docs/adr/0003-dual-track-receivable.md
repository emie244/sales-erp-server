# 应收账款双轨制：业务应收与税务应收并存

本系统对客户应收账款采用「双轨制」记账：业务应收（Business Receivable）和税务应收（Tax Receivable）独立计算并存储。

- **业务应收**：`Σ 已发货订单金额 - Σ 已收款金额`，不论是否开票。所有信用占用、信用限额拦截、账期提醒、欠款风险预警都以这条口径为准。销售老板看的"客户欠多少钱"是这个数。
- **税务应收**：`Σ 已开票金额 - Σ 发票核销金额`。用于税务申报、月度财务报表、对外审计。财务用税控盘开发票时和这条口径绑定。

收款事件 (`PaymentRecord`) 同时影响两条账款：

- 默认情况下，收款挂在 `salesOrderId` 上，扣减业务应收；
- 当财务在「核销」操作中把收款关联到一张或多张已开发票时，通过 `invoice_payment` 多对多表关联，同时扣减税务应收。
- 一笔收款的"业务扣减"和"税务扣减"金额必须相等，但触发时间可能错开。

做这个决定的原因：

1. **中国 B2B 现实**：相当一部分 B 端客户不走对公付款（私账、微信、支付宝），不开税务发票或开票时间远晚于发货。此时业务上客户已经"赊账"，但发票口径看不到，单轨制会让销售/老板对欠款风险无感。
2. **税务合规要求**：增值税申报、企业所得税申报、审计报告都按发票口径走，业务口径无法满足。
3. **两条口径在不同时间会出现差额**：差额 = 已发货未开票金额。这个差额本身是一个有意义的业务指标（潜在开票风险、客户付款节奏）。

权衡：

- **代价**：数据结构和报表复杂度上升约 30%（每个客户两条余额、每笔收款两个核销动作、两套对账报表）。
- **退路**：未来如果所有客户都开始对公走票，可以把税务应收作为唯一口径，业务应收降级为派生视图。

实现顺序：

- Phase 7.1：先实现业务应收（动态计算 + 缓存）+ 信用限额 + 账期提醒。
- Phase 7.2：补充税务应收 + `invoice_payment` 核销表 + 财务对账报表。
