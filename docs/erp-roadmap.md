# ERP 开发路线图：七站漂流补齐计划

> 基于差距分析，按"先风控、后联动、再财务"原则制定。

## 总体原则

1. **先风控、后联动、再财务**。第一道关卡（销售风控）的缺口当前每天都在产生风险，优先级最高。
2. **本地库存层先行**。聚水潭是外部系统，本地库存层是后续所有联动（MRP、发货、凭证）的数据基础。
3. **基础数据先行**。如果客户信用额度、产品底价、BOM 数据没维护好，后续自动化都会跑错。

---

## Phase 0: 基础数据治理（并行，持续进行）

**目标**：补齐"第一站就卡住"的基础数据缺口。

| 任务 | 说明 | 工作量 |
|------|------|--------|
| 客户信用数据批量维护 | 为存量客户录入 `creditLimit`，标记 `isCreditBlocked` | 运营工作 |
| 产品底价批量录入 | 为核心 SKU 录入 `floorPrice` | 运营工作 |
| BOM 准确性审计 | 核对 `bom_headers` + `bom_items` 与实际生产用料是否一致 | 运营工作 |
| 供应商交期基线录入 | 为常用供应商维护默认交货周期 | 运营工作 |

**里程碑**：基础数据完整度达到 80% 以上再启动 Phase 3（MRP）。

**风险**：如果跳过这一步，Phase 1-3 的自动化检查会产生大量误报或漏报。

---

## Phase 1: 销售订单风控检查（1.5 周）

**目标**：让销售订单在创建/提交时真正执行"三道检查"。

| 功能 | 说明 | 对应 Quick Win |
|------|------|---------------|
| `CreditCheckPolicy` | 纯函数策略模块，校验客户信用额度 | #1 |
| `FloorPricePolicy` | 纯函数策略模块，校验 SKU 底价 | #2 |
| `SalesOrder.deliveryDate` | 新增交期字段，DTO + 前端表单 | - |
| `OrderLifecycle` 集成 | create 时底价检查，submit 时信用检查 | #1 #2 |
| 审批表单风控展示 | 飞书表单中显示信用/底价预警信息 | - |
| 配置化风控级别 | `strict` / `warning` / `off` 三档 | - |

**里程碑**：超信用订单和底价击穿订单在提交时被系统拦截（或标红警告）。

**依赖**：无，可立即开始。

**并行建议**：可由后端开发独立完成，前端仅需增加日期选择器和错误提示展示。

---

## Phase 2: 本地库存层（2 周）

**目标**：建立独立于聚水潭的本地库存记录，实现"发货扣减、入库增加"。

| 功能 | 说明 | 对应 Quick Win |
|------|------|---------------|
| `StockLedger` 表 | 出入库流水（SKU、数量、类型、关联单据） | - |
| `LocalStockBalance` 表 | SKU 实时结余（带行锁/乐观锁） | - |
| `StockLedgerService` | 出库扣减、入库增加、余额查询 | #3 #4 |
| `OrderLifecycle.markShipped()` 改造 | 发货时扣减库存，库存不足阻止发货 | #3 |
| 采购订单收货入库 | PO 状态变为 `received` 时增加库存 | #4 |
| 库存流水查询 API | 按 SKU 查询出入库历史 | - |
| 库存余额查询 API | 按 SKU 查询当前结余 | - |

**里程碑**：发货后 `LocalStockBalance` 实时扣减，库存流水可查询。

**依赖**：无强依赖，可与 Phase 1 并行开发（不同模块）。

**关键决策**：`LocalStockBalance` 使用 `SELECT FOR UPDATE` 行锁防止并发超卖。

---

## Phase 3: 供应链联动（3-4 周）

**目标**：建立"销售订单 -> 生产工单 -> 采购申请"的自动链路，实现简化版 MRP。

| 功能 | 说明 |
|------|------|
| `ProductionOrder.salesOrderId` | 生产工单关联销售订单，支持反向查询 |
| 销售订单触发生产建议 | 订单审批通过后，根据 SKU 查询 BOM，对比库存缺口，提示"需生产 X 个" |
| `PurchaseRequest` 模块 | 采购申请（PR）实体 + CRUD API |
| 简化 MRP | 需求 = 订单量 - 可用库存 - 在产数量；缺口自动生成 PR |
| PR 转 PO | 采购员将 PR 转为 PurchaseOrder |
| `PurchaseOrder.expectedDeliveryDate` | 供应商确认交期后回写 |
| 交期变动预警 | 供应商延迟时系统亮红灯，提醒销售沟通 |

**里程碑**：一张销售订单可以一键查看"需要生产多少、采购多少、交期是否受影响"。

**依赖**：必须等 Phase 2 完成（需要准确的本地库存数据做 MRP 计算）。

**风险**：BOM 数据不准确会导致 MRP 结果全错，必须在 Phase 0 中完成 BOM 审计。

---

## Phase 4: 仓库作业规范化（2 周）

**目标**：规范入库和出库的作业流程，支持批次追溯的简化版。

| 功能 | 说明 |
|------|------|
| 生产完工入库界面 | 车间按工单完工后扫码/手动录入入库数量 |
| 入库自动匹配销售订单 | 成品入库后，系统根据 `salesOrderId` 关联，增加可发货库存 |
| 出库单生成 | `markShipped()` 时生成出库单（含 SKU、数量、批次） |
| 出库单传财务标记 | 出库单标记为"已传财务"，作为开票依据 |
| 批次管理（简化版） | SKU 级别批次号记录，不做严格 FIFO |

**里程碑**：车间完工入库 -> 系统匹配订单 -> 库管发货 -> 生成出库单，链路跑通。

**依赖**：依赖 Phase 2（库存层）和 Phase 3（生产工单关联销售订单）。

---

## Phase 5: 业财一体化（4-6 周）

**目标**：出库后自动触发开票，收款后自动核销，实现"业务驱动财务"。

| 功能 | 说明 | 对应差距 |
|------|------|---------|
| `InvoiceRecord` 模块 | 销售发票记录（发票号、金额、开票日期、关联出库单） | 第六站 |
| 开票申请自动触发 | 出库单"已传财务"后，自动生成待审开票申请 | 第六站 |
| `Voucher` 模块 | 会计凭证（借/贷科目、金额、关联单据） | 第六站 |
| 应收凭证自动生成 | 开票时自动生成：借应收账款 / 贷主营业务收入 | 第六站 |
| 收款凭证自动生成 | 回款核销时自动生成：借银行存款 / 贷应收账款 | 第七站 |
| 发票核销 | 收款单勾选未核销发票，勾稽关系记录 | 第七站 |
| 客户对账单 | 按客户展示：订单、出库、发票、收款、未核销余额 | 第七站 |

**里程碑**：一张订单从出库到开票到收款到凭证，全程零手工录入。

**依赖**：依赖 Phase 2（库存数据）和 Phase 4（出库单）。

**风险**：这是最大的深水区，涉及财务合规。建议分两步走：先做发票记录和凭证的**存储/展示**（5.1），再做**自动生成逻辑**（5.2）。

---

## Phase 6: 智能预警与报表（2 周）

**目标**：系统主动发现问题，而不是等人去查。

| 功能 | 说明 | 对应 Quick Win |
|------|------|---------------|
| 账龄分析报表 | 按客户展示应收账龄（30天/60天/90天/超期） | #5 |
| 逾期预警 | 超期欠款客户自动标红，锁单预警 | 第六站 |
| 交期预警 | `deliveryDate` 临近但尚未发货的订单自动提醒 | - |
| 库存不足预警 | `LocalStockBalance` 低于安全库存的 SKU 自动提醒 | - |
| 信用额度预警 | 客户已用额度接近上限时，在订单列表中黄色标记 | - |

**里程碑**：管理员每天打开系统，优先看到"今天需要处理的风险清单"。

**依赖**：依赖 Phase 1-5 的数据积累。

## 两条可选路径

### 路径 A：最小可行（MVP，8-10 周）

只实现核心风控 + 库存 + 账期报表，跳过 MRP 和业财自动化：
- Phase 0（基础数据）
- Phase 1（风控）
- Phase 2（库存层）
- Phase 6 中的**账龄报表 + 逾期预警**（Quick Win #5）

**适用场景**：团队资源有限，先堵住最大的业务风险（信用、底价、库存不准、逾期不回款）。

### 路径 B：完整闭环（14-16 周）

按上述六阶段全部实现。

**适用场景**：有专职开发团队，目标是实现视频中的"七站漂流"完整链路。
